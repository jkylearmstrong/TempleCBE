# 0.7.0 removal plan for the deprecated wrappers

Status: **plan, nothing removed.** Written 2026-10-21 from a scan of `master` at 0.6.3. Removal was announced for 0.6.0 and re-scheduled to 0.7.0 in the 0.6.1 notes (`NEWS.md`).

## What is scheduled

66 wrapper functions carry `lifecycle::deprecate_warn("0.5.8", ...)` and are announced for removal in 0.7.0. Each is a thin wrapper that warns and calls its replacement. `cbe_*` names that are presentation and formatting functions (themes, palettes, scales, plots, report tables, number formatters) are **not** part of this: see `CLAUDE.md`.

## Findings of the scan

0. `write_xlsx()` is also deprecated for 0.7.0 removal (its `deprecate_warn()` call spans several lines, so the scan below does not list it; add it to the removal).
1. **No package code calls a deprecated function.** Outside the wrappers' own definitions and their `deprecate_warn()` strings, the only mentions in `R/` are comments. Removing the wrappers does not change any other function.
2. **Tests use the old names heavily** (about 380 call-like uses). Many exist to test the wrappers themselves; the rest are older tests that were never moved to the new names.
3. **Vignette sources, README and templates still use the old names**, so a user who copies a template gets the deprecation warning today, and an error after removal: `README.md` and `README.qmd` (21 mentions each), `vignettes/sas_survival.Rmd`, `R_to_SAS.Rmd`, `eda_and_missingness.Rmd`, `pca_analysis.Rmd`, `reticulate_export.Rmd`, `nested_survival_cv.Rmd`, the `inst/templates/*.qmd` and `inst/rmarkdown/templates/*/skeleton` files, and `scripts/deploy_release.R`. The generated `vignettes/*.html` are stale copies and follow the sources.
4. **Three wrappers mask other packages' functions**: `clean_names()` (janitor), `like()` (data.table) and `render()` (rmarkdown), plus the `%like%` operator. Removing them also ends the masking, which is an improvement for users who attach TempleCBE and those packages together.
5. The package already ships `find_deprecated_calls()`, which scans a user's project for these names (a single compiled pattern, fast), and `update_deprecated_calls()`; the old-to-new table they use is in `R/deprecated_tools.R` and must be kept in step with the list below. They are the migration tools to point users at.

6. **Not every wrapper is a pure pass-through.** Found while migrating the tests (2026-10-22): the deprecated `clean_names()` returns plain `janitor::clean_names()` output and stops with "Input must be a character vector or data frame" for other input, whereas its named replacement `clean_names_keep_labels()` also stores the original names as variable labels and leaves other input to janitor. Migrating `clean_names(df)` to `clean_names_keep_labels(df)` therefore changes the result (labels attached); `janitor::clean_names()` is the like-for-like replacement for data frames. `test-clean_names.R` still tests the wrapper for that reason. Before the removal PR, check each wrapper against its replacement the same way (argument defaults, return values, error messages); the other 65 were compared on 2026-10-23, see 'Parity of the wrappers'.

## Steps

1. **Migrate first, remove second.** In one PR per area, switch to the new names: tests (keep one test file that asserts each wrapper still warns, until the removal PR deletes it), vignette sources and README, templates and skeletons, `scripts/deploy_release.R`. Re-render the vignettes so the `.html` files follow. No behaviour change; L1 to L2.
2. **Announce.** Publish a 0.6.x or 0.7.0-pre note that removal is next, pointing to `find_deprecated_calls()` and the table below.
3. **Remove** (L3: it changes the public API). Delete the wrapper definitions and their `export()` lines in `NAMESPACE`, the generated `man/*.Rd` files, the `deprecated_tools.R` entries that list them, and their entries in `_pkgdown.yml`; delete the deprecation test file. Run `devtools::document()`, `R CMD check` on Ubuntu, Windows, macOS and aarch64, and a `find_deprecated_calls()` scan of this repository, which must come back empty.
4. **Release** as 0.7.0 (minor release: L3, written maintainer sign-off).

## Parity of the wrappers with their replacements (checked 2026-10-23)

Method: an R script loaded the package and compared, for each of the 66 `lifecycle` wrappers and `write_xlsx()`, the argument names and defaults of the wrapper and its replacement, and the wrapper's body (everything but the deprecation warning). Signatures and bodies were read; no wrapper was run against its replacement.

| Class | Count | Meaning |
|-------|------:|---------|
| Pure pass-through | 61 | One call to the replacement with the same arguments (60 as `new(<same arguments>)`; `extract_win_posix_paths()` passes `xlsx_token_re` by name); identical argument names and defaults. Removal changes nothing for a caller that has switched to the new name. |
| Re-dispatch | 3 | `cbe_cox_multi()`, `cbe_cox_single()`, `cbe_km_single()` rebuild the call with `match.call()` and evaluate it as `TempleCBE::cox_multi` and so on: the same as calling the new function with the same arguments. |
| Pass-through with a label | 1 | `summarize_tune_results()` forwards every argument to `tune_alpha_by_split()` and adds `.fn_name = "summarize_tune_results"`: only the name that the `on_complete` event reports differs. |
| Equivalent by another route | 1 | `write_xlsx()` calls `writexl::write_xlsx(...)`; its named replacement `write_xlsx_file(x, path, ...)` calls `writexl::write_xlsx(x = x, path = path, ...)` after a `check_installed()`: the same result. |
| **Not equivalent** | 1 | `clean_names()`: see finding 6 above. A caller must choose `janitor::clean_names()` (like for like for data frames) or accept the labels of `clean_names_keep_labels()`. |

The deprecated functions the first scan did not list (it read only `deprecate_warn("0.5.8", ...)` calls written on one line):

* `%like%` (exported; a plain `warning()` that points to `match_like()`), and `%notin%` (not exported since 0.5.9).
* The three replacement functions `cbe_dataset_label<-`, `cbe_database_name<-` and `cbe_database_label<-` (exported; they warn and call `dataset_label<-` and so on).
* `write_xlsx()` (already noted).

That makes **71 exported names** to remove (66 + `write_xlsx()` + `%like%` + 3 replacement functions), and one unexported helper (`%notin%`). The `cbe_*` exports that remain are presentation and report functions (plots, palettes, themes, `cbe_cox_table()`, `cbe_exact2x2_ci()`, labels and tables); this plan did not re-judge each of them against the naming rule in `CLAUDE.md`.

Things to keep when the wrappers go: `find_deprecated_calls()` and `update_deprecated_calls()` read the old-to-new table in `R/deprecated_tools.R`. After the removal they are the way for a user to find what to rename, so the table must stay (it names functions that no longer exist), and its tests must be changed from 'the wrapper warns' to 'the tool still finds and rewrites the old call'.

## Decisions needed

* Remove all 66 in 0.7.0, or keep any longer? (`render()`, `like()` and `clean_names()` mask other packages, which argues for removal; `cbe_*` analysis wrappers are used by existing report templates, which argues for a longer notice.)
* Is one more minor release with the warnings only (a 0.6.x) wanted before removal?
* Do downstream projects (the CBE report repositories) need a migration window, and should `find_deprecated_calls()` be run on them first?

## Not covered

* Calls made from user projects outside this repository (only `find_deprecated_calls()` run on them can say).
* Calls built dynamically (`do.call("cbe_cox_single", ...)`, `match.fun()`), which a text scan can miss.
* Whether any of the replacement functions differs in behaviour from its wrapper: the wrappers pass arguments through, but that was read, not tested for every function.
